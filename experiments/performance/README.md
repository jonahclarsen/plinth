# Performance investigation

Run `.github/workflows/performance.yml` on the standard `macos-15` runner. No production optimization is adopted by these experiments. `prepare.mjs` deliberately edits tracked application files: run it **only in a disposable CI checkout**. It resets candidates from the current commit before applying each experiment.

The frontend harness builds the production Svelte app, then measures it in macOS Playwright WebKit with a synthetic Tauri bridge (96 and 480 fictional records). This isolates frontend costs from native persistence. Each case has a warmup and five AB/BA paired repetitions, each containing 90 frame-paced input events. Report median work time, p95 frame intervals, animation callbacks, style mutations and geometry reads. Input work includes microtask flushing and a forced layout read; this is not input-to-photon latency. Frame intervals include actual animation callbacks but a hosted WebKit process does not reproduce the installed app's WindowServer/GPU workload. SVG artwork is deliberately cheap; image decoding and texture memory need a separate experiment with realistic synthetic rasters.

Candidates: apply radius immediately to resting covers while keeping swing animation on hovering/returning covers; cache unscaled cell geometry between layout changes; compact native JSON; index album lookups in native history descriptions. Baseline/candidate benchmark runs are sequential, alternate order, and share a runner. Browser cold-cache cost is retained separately. Pointer correctness is checked for every event. Existing hover, geometry, history and monitor-targeting behavior tests run on the combined frontend candidate. Cache invalidation on every future layout/transform change would need review before adoption.

Native release binaries use the real `library::save`, history read, atomic write, backup and navigation code. Each sample starts from 20 or 100 retained synthetic states and performs ten changed-settings saves plus history-list reads. Five rounds alternate variant order. Native tests run on all three binaries. All data lives in temporary directories; the real library is never opened. JSON compaction preserves the document schema, backup, atomic rename and retained states. No claim is made about end-to-end IPC, native idle CPU, power use, window placement or focus.

Raw measurements and runner metadata are uploaded as `performance-results`; generated application builds and fixtures stay out of Git. No UI design changes are made, so the README screenshot does not change.

The follow-up run adds a CSS radius candidate that avoids per-cover resting style writes, and an offscreen culling candidate that keeps full-library geometry while mounting only visible rows plus two rows of overflow allowance. Hover-size follow-up measurements hold the slider to exercise the live sample. The initial run measured Hover size without holding (a settings-update control). Artifacts now live under `.local/performance`, outside Playwright's disposable output directory, and frontend results upload before the native phase.
